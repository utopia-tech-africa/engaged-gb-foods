# GBfoods Stock Control

Field and client platform for the GBfoods nationwide depot sorting and segregation programme in Ghana. QC crews capture attendance, stock counts, and photo evidence at distributor depots. Supervisors verify. GBfoods records quality dispositions.

## Built today

- Turborepo monorepo with `apps/web` (Next.js) and `apps/api` (NestJS)
- Biome + Husky pre-commit hooks
- Prisma + PostgreSQL, health endpoint, Swagger
- Auth: field staff ID + PIN, ops/client email + password, sessions, `/auth/me`
- Role shells for field, ops, and GBfoods client
- Network master data: 16 Ghana regions, distributors, depots (optional recce lat/lng), QC assignments
- Ops UI: `/ops/regions`, `/ops/distributors`, `/ops/depots`, `/ops/attendance`
- Field attendance: photo check-in/out with optional GPS (no geofencing), R2 or local uploads
- Field UI: `/field`, `/field/check-in?depotId=…`, `/field/stock`, `/field/visits/[id]/reconcile`
- Stock capture with zones, evidence, and opening movements
- Visit reconciliation: balance by SKU/batch, custodians on held lots, three signatures, close or exception
- GBfoods disposition on stock lots (`POST /stock-lots/:id/disposition`) with zone lock for release paths
- Ops visit review: `/ops/visits/[id]`; GBfoods control room: `/client`, `/client/depots/[id]`, `/client/lots/[id]` with overview KPIs, filters, CSV exports, and depot packs
- Depot recce (`/ops/recce`, `/recces`): checklist, gaps with owner and deadline, optional photo keys, ready/hold decision synced to `Depot.readiness`; a critical gap forces hold
- People and assignments (`/ops/people`, `/ops/assignments`; API `/users`, `/assignments`, `/clusters`): admin and national ops create, edit, deactivate users and reset PINs (field roles) or passwords (desk roles); field roles need staff ID + PIN, desk roles need email + password; assign field users to a distributor, cluster, or region with dates and end assignments. Credential hashes are never returned. Deactivating or resetting credentials revokes the user's sessions
- Training assessment roster (`/ops/assessment`, `/assessments`, `/users`): safety, quality, and record-keeping must all pass; any fail means not dispatchable
- Field exceptions and escalations (`/field/escalations/new`, `/ops/escalations`, `/escalations`): trigger, note, and photos create a timestamped escalation; ops list open items and update status, owner, due date, and written record. Raising one does not change the visit status. Online only for now
- GBfoods brand tokens and logo assets
- Installable PWA (Serwist service worker, web manifest, `/~offline` fallback) and an offline field queue for depot check-in/out and new stock lots, with sync on reconnect
- Web data layer: Orval-generated React Query hooks from the committed OpenAPI spec (no hand-written fetch wrappers for JSON endpoints)

## Not built yet

- Offline queueing for reconcile, visit close, and disposition (these stay online-only)
- Offline caching of SKU and depot lists (open the check-in or stock form once while online before going offline)
- Server-side draft model (server never exposes unsynced drafts to client)

See `PRD.md` for the full product definition.

## Setup

```bash
pnpm install
cp apps/api/.env.keep apps/api/.env
# edit DATABASE_URL and other vars in apps/api/.env
cp apps/web/.env.keep apps/web/.env.local
pnpm --filter @gbfoods/api prisma:generate
pnpm --filter @gbfoods/api exec prisma migrate dev --schema prisma/schema.prisma
# includes migrations `reconcile_disposition`, `client_control_room` (Visit.lastSyncedAt), `escalation`
pnpm --filter @gbfoods/api seed:auth
pnpm --filter @gbfoods/api seed:network
```

## PWA and offline field queue

- The service worker is generated by Serwist (`apps/web/src/app/sw.ts` to `apps/web/public/sw.js`, git-ignored). It is **disabled in development** and any old registration is removed. To test install and offline behaviour, run a production build: `pnpm --filter @gbfoods/web build && pnpm --filter @gbfoods/web start` (use `localhost` or HTTPS).
- Manifest: `apps/web/public/manifest.webmanifest` (name "GBfoods Stock Control", theme `#fe5000`, `start_url` `/field`).
- Document navigations that fail offline show `/~offline`.
- **Check-in/out** (`/field/check-in`) and **new stock lot** (`/field/stock/new`) try the online path first. If the device is offline, or a request fails with a network error, the record and its photos are stored in IndexedDB (`gbfoods-field-offline`, store `field-outbox`) and the form shows "Saved offline — will sync when online".
- Queued records sync oldest-first when the browser comes back online and a user is signed in, or when the user taps **Sync now** in the field status bar. Photos upload through the normal R2/local upload path at sync time. A network error, 401, 408, 429 or 5xx stops the run and keeps the queue; any other 4xx drops that record and shows an error toast.
- The field status bar (all `/field` pages) shows online/offline state, pending count and last sync time. "Last synced" is stored in `localStorage` key `gbfoods.field.lastSyncedAt` as the time (`Date.now()`) the API last accepted a queued record.
- Code: `apps/web/src/lib/field/` (outbox, enqueue, flush), `apps/web/src/components/field-sync-status.tsx`, `field-offline-sync-listener.tsx`, `pwa-provider.tsx`.

## API client (OpenAPI + Orval)

The API publishes OpenAPI at `/api/v1/docs-json`. The spec is committed at `apps/api/openapi/openapi.json` and the generated React Query client is committed at `apps/web/src/lib/api/generated`, so `pnpm typecheck` works without a running API or database.

After any API change (controllers, DTOs, response types), regenerate both, in this order:

```bash
pnpm --filter @gbfoods/api docs:openapi
pnpm --filter @gbfoods/web generate:api
```

- `docs:openapi` compiles the API with `tsc` and exports the spec (it needs the compiled decorator metadata, so it does not run through `tsx`). It does not need a database connection.
- Do not edit files under `apps/web/src/lib/api/generated` by hand.
- Components import hooks such as `useGetRegions`, `usePostDepots` from `@/lib/api/generated/<tag>/<tag>`. Mutations take `{ data }` (plus `id` for path params).
- `apps/web/src/lib/api/custom-fetch.ts` is the Orval mutator. It sends `Authorization: Bearer <accessToken>` from the stored session when one exists, and throws `ApiError` with the Nest `message`.
- Photo bytes are the only special case: `apps/web/src/lib/uploads.ts` PUTs to the presigned R2 URL (or falls back to the generated local upload call) and loads private images as blobs.

## Environment variables

Documented here instead of an `.env.example` file. Copy from the `.env.keep` stubs.

| Name | Example | App |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://portfolio:portfolio@localhost:5436/gbfoods_stock?schema=public` | API |
| `HOST` | `0.0.0.0` | API |

| `JWT_ACCESS_SECRET` | long random string (32+ chars) | API |

| `JWT_REFRESH_TTL_DAYS` | `14` | API |

| `NEXT_PUBLIC_API_BASE_URL` | `http://localhost:4000/api/v1` | Web |
| `R2_ACCOUNT_ID` | Cloudflare account id | API (optional locally) |
| `R2_ACCESS_KEY_ID` | R2 API token access key | API (optional locally) |
| `R2_SECRET_ACCESS_KEY` | R2 API token secret | API (optional locally) |
| `R2_BUCKET` | bucket name | API (optional locally) |
| `R2_PUBLIC_BASE_URL` | `https://pub.example.r2.dev` | API (optional locally) |

When all `R2_*` variables are set, attendance photos use presigned PUT uploads to Cloudflare R2. If they are omitted, use `POST /api/v1/uploads/local` (multipart field `file`); files are stored under `apps/api/.uploads` and object keys are prefixed with `local/`.

### Local attendance smoke test (no R2)

```bash
# Sign in as QC (see seed accounts), then:
TOKEN="$(curl -s -X POST http://localhost:4000/api/v1/auth/field/sign-in \
  -H 'Content-Type: application/json' \
  -d '{"staffId":"BTL-0031","pin":"2468"}' | jq -r .accessToken)"

curl -s -X POST http://localhost:4000/api/v1/uploads/local \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@/path/to/tiny.jpg;type=image/jpeg"

# Use returned objectKey in attendance (replace DEPOT_ID from GET /assignments/me/depots):
curl -s -X POST http://localhost:4000/api/v1/attendance \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"depotId":"DEPOT_ID","kind":"check_in","photoObjectKey":"local/….jpg","latitude":5.6,"longitude":-0.2,"accuracyMeters":12}'
```
